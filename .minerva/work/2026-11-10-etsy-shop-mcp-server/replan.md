# Replan log: etsy-shop-mcp-server

## 2026-11-10 — Closed client list instead of open registration and a consent page

**Original plan**: Dynamic client registration open to anyone, but accepted only for ChatGPT's and Claude's documented redirect URIs. An approval page names the requesting client before the Etsy sign-in. The Etsy user+shop allowlist is the second layer.
**What changed**: Phase 2 review found that those redirect URIs are shared by every Claude and ChatGPT user. An attacker could add her server to their own account and send her a convincing connect link, and the only thing between them and her shop would be the client's own `state` handling. Open registration also lets anyone write to Workers Free KV (1,000 writes a day). The owner (user-directed, 2026-11-10): this is not a public app, so there should be no sign-up or consent; a list we control decides who can connect at all.
**New plan**: No dynamic registration: `/register` doesn't exist and the metadata advertises none. The only clients are those in the `MCP_CLIENTS` secret: id, name, a secret of 32+ characters, and exact redirect URIs. They are confidential clients, so a code is useless without that app's secret. The Worker provisions them into the provider through its public `updateClient`, re-checks the client id against the list on `/authorize`, `/token` and every `/mcp` call (removing an entry cuts that app off immediately), and fails closed when the list is missing or malformed. `/authorize` goes straight to the Etsy sign-in (the provider's guidance: a server whose clients are all pre-registered, with no dynamic registration, doesn't need per-client consent). The Etsy single-use state, the allowlist, the vault and everything else are unchanged. Claude (custom connector → Advanced settings) and ChatGPT ("user-defined OAuth client") both accept a pre-registered client id and secret.
